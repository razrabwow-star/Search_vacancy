# Монитор вакансий бизнес-/системных аналитиков

Ежедневная проверка Т-Банка, Яндекса, Альфа-Банка, ВТБ, RWB и Авито. География — Москва или дистанционная работа. Первый рабочий запуск отправляет начальный список, следующие — новые подходящие вакансии. Telegram получает отчёт и при отсутствии новых вакансий, и при ошибке источника.

Сбер отключён. Вход в аккаунты и браузер для действующих источников не нужны. Docker-образ использует Python, SQLite и HTTP-запросы, без Chromium.

## Установка на Ubuntu

Подключение из Windows PowerShell:

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519" root@IP_СЕРВЕРА
```

Первая установка на сервере, где уже установлен Docker Compose:

```bash
sudo git clone https://github.com/razrabwow-star/Search_vacancy.git /opt/vacancy-monitor
cd /opt/vacancy-monitor
sudo cp .env.example .env
sudo chmod 600 .env
sudo nano .env
sudo mkdir -p data
sudo chown -R 10001:10001 data
sudo chmod 700 data
sudo docker compose build
```

Заполните TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID. Действующие источники:

```env
SOURCES=tbank,yandex,alfa,vtb,rwb,avito
```

Отправьте /start своему боту. Чтобы узнать chat ID:

```bash
sudo docker compose run --rm monitor chat-id
```

## Первый запуск

Тест без отправки Telegram, с отдельной базой:

```bash
sudo docker compose run --rm monitor run --dry-run
```

Рабочий запуск:

```bash
sudo docker compose run --rm monitor run
```

Таймер — ежедневно около 09:00 по Москве; пропущенный запуск выполняется после включения сервера:

```bash
sudo cp deploy/vacancy-monitor.service deploy/vacancy-monitor.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now vacancy-monitor.timer
sudo systemctl list-timers vacancy-monitor.timer
```

Установка в другую папку требует изменения WorkingDirectory в service-файле. Во время прогона контейнер существует, после завершения удаляется; база остаётся в data.

## Обновление существующей установки

Дождитесь завершения текущего прогона. В SSH-консоли Ubuntu:

```bash
cd /opt/vacancy-monitor
sudo git pull --ff-only
sudo nano .env
```

Замените SOURCES на tbank,yandex,alfa,vtb,rwb,avito. Git не меняет ваш .env автоматически. Токен, chat ID и data сохраняются.

```bash
sudo docker compose build
sudo docker compose run --rm monitor run --dry-run --sources vtb,rwb,avito
sudo docker compose run --rm monitor run
```

Существующий таймер продолжит работать с новым образом, повторная установка не требуется. Не используйте compose down -v и не удаляйте data: там история обработанных вакансий.

## Источники и полнота

- Т-Банк: публичный API, московская и общая выдачи с пагинацией, описания аналитических вакансий.
- Яндекс: публичный API с курсором, города и форматы работы из метаданных, HTML описаний.
- Альфа-Банк: публичный API и справочник городов, обход всех страниц.
- ВТБ: встроенные данные Next.js на официальном сайте. Два обхода: Москва и фильтр удалённой работы по стране. Сверяются номера страниц и число уникальных вакансий с found. Общая выдача ВТБ ограничена 2000 карточками; отдельные нужные выборки позволяют избежать этой потери.
- RWB: публичный список с limit/offset и общим count; полные описания аналитиков через API карточек. Данные контактов сотрудников не сохраняются.
- Авито: публичный ответ фильтра action=filter с полным HTML каталога. Главная HTML-страница содержит лишь превью; её не используем как полный список. Число уникальных карточек сверяется с суммой счётчиков направлений. Формат работы берётся из подписи карточки, не из неоднозначного data-vacancy-remote.

Ошибка страницы, карточки или расхождение количества даёт неполный отчёт. Успешно полученные вакансии сохраняются даже при сбое следующей страницы. Это не считается отсутствием вакансий.

Правила исключают аналитиков данных, финансовых, продуктовых и маркетинговых аналитиков. Для вакансии с общим названием «аналитик» нужны несколько признаков работы с требованиями и процессами в описании. Правила не понимают все ограничения естественного языка: перед откликом проверяйте условия работодателя.

## Обработка и уведомления

Ключ вакансии — источник + стабильный ID. Каждая полученная вакансия при каждом прогоне записывается в observations, включая неподходящие и ошибки обработки; обновляется last_processed_run_id. Не полученные из-за сетевой ошибки вакансии не выдаются за обработанные.

Новое событие создаётся при первом подходящем обнаружении или переходе «не подходила → подходит». Повторный обход и редактирование уже подходящей вакансии не создают повторного уведомления. Разные ID считаются разными вакансиями.

Исчезновение отмечается после двух успешных полных обходов источника. Ошибки не увеличивают этот счётчик. У ВТБ это отсутствие в московской и удалённой выборках, не подтверждение закрытия работодателем.

Telegram-сообщения хранятся в очереди до успешной отправки. После сбоя очередь повторяется на следующем прогоне. При аварии между фактической отправкой и записью подтверждения возможен повтор одной части сообщения.

```bash
sudo docker compose run --rm monitor status
sudo docker compose run --rm monitor retry-notifications
sudo journalctl -u vacancy-monitor.service -n 100 --no-pager
```

Коды выхода: 0 — успех, 2 — неполная проверка источников, 1 — ошибка запуска/отправки. Таймер принимает код 2: причина уже включена в отчёт.

## Данные и ресурсы

.env и data исключены из Git. Токен, ключи и сохранённые сессии не публикуйте. SQLite и история постепенно растут; проверяйте свободное место и делайте резервные копии data после завершения прогона.

TLS-проверка включена. Для сертификатов банков используется публичный Russian Trusted Root CA внутри HTTP-клиента; происхождение и отпечаток — в certs/README.md. Системное хранилище Ubuntu не изменяется.

Лимит контейнера — 700 МБ, сбор последовательный. Docker-сборка и фактическое потребление памяти на Ubuntu требуют проверки на сервере. Локальные проверки описаны в VALIDATION.md.
