# Монитор вакансий аналитиков

Python + SQLite + Docker. Раз в день проверяет Т-Банк, Яндекс, Альфа-Банк и авторизованный каталог Сбера. География: Москва и полностью дистанционная работа. Направления: бизнес-/системный анализ, включая BPM-аналитиков. Все уровни опыта.

## Что готово и что нужно проверить

Три публичных сборщика используют реальные запросы сайтов, включая пагинацию. Сбер использует Playwright и сохранённую сессию: после первого ручного входа обязательно проверьте его отдельно. Схема закрытого каталога до входа не подтверждена; неизвестный формат или отсутствие подтверждённого общего числа вакансий считается ошибкой. Сервис не выдаёт такой результат за «вакансий нет».

Сервис подготовлен локально. Он ещё не установлен на вашем сервере. Запуск Docker и потребление памяти на Ubuntu необходимо проверить там. На 1 ГБ RAM запускается только один браузер; если сервер занят другими задачами, памяти может не хватить. Таймер запускает контейнер раз в сутки, после работы он удаляется, данные остаются.

Фактические результаты локальных проверок — в `VALIDATION.md`.

## Подключение к серверу из Windows

В PowerShell или Windows Terminal:

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519" root@IP_СЕРВЕРА
```

Замените IP и при необходимости имя пользователя. Если ключ расположен иначе, укажите полный путь к приватному ключу (без `.pub`). Нестандартный порт: `ssh -p 2222 -i "C:\путь\ключ" root@IP_СЕРВЕРА`. При первом входе проверьте отпечаток сервера по данным провайдера.

## Перенос и сборка

Можно установить напрямую из GitHub. В SSH-консоли Ubuntu (для первой установки в ещё не существующую папку):

```bash
git clone https://github.com/razrabwow-star/Search_vacancy.git /opt/vacancy-monitor
cd /opt/vacancy-monitor
cp .env.example .env
chmod 600 .env
mkdir -p data
chown 10001:10001 data
chmod 700 data
docker compose build
```

Если репозиторий закрытый, потребуется доступ GitHub на сервере. SSH-ключ для входа на сервер и доступ сервера к GitHub настраиваются независимо. Если Git не установлен, установите его через `sudo apt-get install git`.

Далее переходите к разделу Telegram. Перенос архивом ниже — альтернативный вариант.

Загрузите подготовленный архив из PowerShell (путь к архиву замените на свой):

```powershell
scp -i "$env:USERPROFILE\.ssh\id_ed25519" "C:\путь\vacancy-monitor.tar.gz" root@IP_СЕРВЕРА:/tmp/
```

Для нестандартного порта у `scp` используется большая `-P`, например `scp -P 2222 ...`.

В SSH-консоли Ubuntu:

```bash
mkdir -p /opt
tar -xzf /tmp/vacancy-monitor.tar.gz -C /opt
cd /opt/vacancy-monitor
cp .env.example .env
chmod 600 .env
mkdir -p data
chown 10001:10001 data
chmod 700 data
docker compose version
docker compose build
```

Архив не содержит `.env`, базы или авторизационной сессии. Не распаковывайте новый архив поверх уже настроенного сервиса без резервной копии: команды подготовки предназначены для первой установки. Для ежедневного запуска образ собирается один раз.

## Telegram

Создайте бота через официальный @BotFather в Telegram. Токен запишите в `.env` на сервере:

```bash
nano .env
```

`TELEGRAM_BOT_TOKEN=...` — токен бота. Отправьте `/start` своему боту, затем выполните:

```bash
docker compose run --rm monitor chat-id
```

Команда покажет chat_id и имя чата, без содержимого сообщений. Запишите нужный ID в `TELEGRAM_CHAT_ID` в `.env`. Для групп нужен ID группы; бот должен иметь право писать в неё. Токен и приватный SSH-ключ не присылайте в чат.

В `.env` по умолчанию подключены все четыре источника. Пока Сбер не настроен, можно временно поставить `SOURCES=tbank,yandex,alfa`; иначе отчёт будет сообщать, что Сбер не проверен.

## Вход в Сбер на Windows

Сохранение сессии выполняется локально на Windows, где есть браузер и возможность вручную ввести код. Установите Python 3.12, если он отсутствует, и распакуйте ту же папку `vacancy-monitor` на компьютере. В PowerShell из этой папки:

Архив можно распаковать встроенной командой Windows: `tar -xzf .\vacancy-monitor.tar.gz`, затем `cd .\vacancy-monitor`.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m monitor login-sber --data-dir data
```

Откроется отдельное окно браузера. Войдите по телефону/почте/Сбер ID, откройте каталог вакансий без фильтров, затем нажмите Enter в консоли. Скрипт сохранит `data/sber-state.json` и `data/sber-session-storage.json` (cookies, состояние IndexedDB и sessionStorage).

Проверьте сборщик локально:

```powershell
.\.venv\Scripts\python.exe -m monitor run --dry-run --sources sber --data-dir data
```

Если источник отмечен как полностью проверенный, перенесите оба файла:

```powershell
scp -i "$env:USERPROFILE\.ssh\id_ed25519" .\data\sber-state.json .\data\sber-session-storage.json root@IP_СЕРВЕРА:/opt/vacancy-monitor/data/
```

На сервере:

```bash
cd /opt/vacancy-monitor
chown 10001:10001 data/sber-state.json data/sber-session-storage.json
chmod 600 data/sber-state.json data/sber-session-storage.json
docker compose run --rm monitor run --dry-run --sources sber
```

Если проверка не подтверждает полноту или авторизацию, подключение Сбера ещё не закончено. Причина выводится в отчёте. Некоторые сессии зависят от IP/устройства и могут не переноситься на сервер; тогда потребуется вход из браузера на сервере. Без этой проверки не включайте Сбер в подтверждённые рабочие источники. Сессию не кладите в Git и не публикуйте. При истечении входа повторите этот раздел и замените файлы.

## Первый запуск и расписание

Сначала без Telegram, с отдельной тестовой базой:

```bash
cd /opt/vacancy-monitor
docker compose run --rm monitor run --dry-run
```

Затем рабочий запуск — первый отчёт отправит все подходящие вакансии как начальный список:

```bash
docker compose run --rm monitor run
```

Установка таймера (ежедневно около 09:00 по Москве):

```bash
cp deploy/vacancy-monitor.service deploy/vacancy-monitor.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now vacancy-monitor.timer
systemctl list-timers vacancy-monitor.timer
```

`Persistent=true` запускает пропущенную проверку после включения сервера. Пересекающиеся запуски блокируются файловой блокировкой. Если проект установлен не в `/opt/vacancy-monitor`, исправьте `WorkingDirectory` в service-файле до установки. Для пользователя без root команды установки в `/opt` и systemd выполняются через `sudo`.

## Повторные уведомления и ошибки

Каждая успешно полученная вакансия, включая неподходящие, сохраняется с `first_seen`, `last_seen` и `last_processed_run_id`. Таблица `observations` содержит историю всех проверок: `matched`, `rejected` или `error` и причину. Ошибка получения описания сохраняется как ошибка и не считается успешной проверкой. Сбой всей выдачи — ошибка источника; ранее известные вакансии остаются в базе.

Уникальность: `источник + ID`. Событие создаётся при первом обнаружении подходящей вакансии или при переходе «не подходила → подходит». Редактирование уже подходящей вакансии и повторное появление того же ID не создают нового уведомления. Новый ID считается новой вакансией; смысловые дубликаты с разными ID не объединяются автоматически.

Запись вакансии, её обработки и события выполняется одной транзакцией. Отчёт и его части сохраняются в очереди до отправки. Отправленные части не повторяются при обычном восстановлении. При сбое между фактической отправкой Telegram и записью подтверждения возможен повтор одной части — Bot API не предоставляет ключ идемпотентности для sendMessage.

`--dry-run` использует отдельную базу `dry-run.sqlite3` и имитирует подтверждение отчёта только в ней. Повторный тестовый запуск показывает только новые события; реальная отправка и рабочая база не затрагиваются.

Исчезновение отмечается как `missing` после двух успешных полных обходов источника. Это означает «больше не обнаруживается», а не подтверждённое работодателем закрытие. Ошибка/неполная выдача не увеличивает этот счётчик.

```bash
docker compose run --rm monitor status
docker compose run --rm monitor retry-notifications
journalctl -u vacancy-monitor.service -n 100 --no-pager
```

Коды завершения: `0` — проверка/команда завершена, `2` — один или несколько источников не полностью проверены, `1` — ошибка запуска или доставки. Systemd принимает `2`, потому что сообщение о неполной проверке уже отправлено; детали смотрите в Telegram. При ошибке Telegram очередь остаётся в базе и повторяется на следующем рабочем прогоне или через `retry-notifications`.

## Обновление через Git

Перед обновлением дождитесь завершения текущего прогона (`systemctl status vacancy-monitor.service`). Из установленной папки:

```bash
cd /opt/vacancy-monitor
git pull --ff-only
docker compose build
```

Следующий ежедневный прогон использует новый образ. `.env`, база и сессия находятся вне Git и сохраняются. При изменении файлов таймера или service повторно скопируйте их в `/etc/systemd/system/` и выполните `systemctl daemon-reload`.

## Фильтры и ограничения

Москва проверяется по метаданным города или отдельной московской выдаче Т-Банка. Для других городов нужны явный дистанционный формат без гибрида либо формулировка «полностью дистанционно» в условиях. Слова об удалёнке в обязанностях и дистанционном обучении не используются как подтверждение. Очевидные требования проживания вне Москвы, посещения офиса или удалёнка только после адаптации исключаются.

Правила не понимают все территориальные/правовые ограничения естественного языка. Проверяйте условия в карточке перед откликом. Неоднозначные вакансии без подтверждённого города/формата исключаются. Финансовые, продуктовые, маркетинговые и data-аналитики исключаются по названию; аналитики с общим названием включаются при нескольких признаках работы с требованиями/процессами.

Внутренние API сайтов могут меняться. Сбер распознаёт распространённые имена полей JSON и кнопки пагинации, но его работа требует проверки после входа. Если Сбер не отдаёт общее количество или использует другое представление, нужно уточнить сборщик по фактическому ответу. Для вакансий Сбера без ссылки в ответе уведомление ведёт на каталог.

## TLS и память

Docker содержит публичный Russian Trusted Root CA из уже доверенного хранилища Windows; отпечаток и происхождение записаны в `certs/README.md`. Он нужен для сертификатов банков. Корень используется внутри приложения и его браузера, системное хранилище Ubuntu не меняется. TLS-проверка включена. Если банк сменит цепочку, обновите доверенный сертификат из проверенного источника и пересоберите образ.

Контейнер ограничен 700 МБ; Chromium запускается последовательно и использует диск вместо маленького `/dev/shm`. Не запускайте локальный сбор и другие тяжёлые контейнеры одновременно на сервере с 1 ГБ. OOM будет виден в журнале Docker/systemd. Лимит можно настроить в compose после измерений.

База и история постепенно растут. Периодически контролируйте место (`du -sh data`) и делайте резервную копию. Для простой согласованной копии остановите таймер, убедитесь, что service не выполняется, и скопируйте всю папку data, затем включите таймер. Копия также содержит секретную сессию Сбера — храните её с ограниченным доступом.

## Локальные тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют повторные прогоны, переход к релевантности, ошибки карточек, историю обработки, исчезновение вакансий, повторную отправку очереди, фильтры и разбиение длинных сообщений. Они не подтверждают авторизацию Сбера, отправку в ваш Telegram или работоспособность Docker на вашем сервере.
